# 温湿度监控业务流程

## 整体流程

```text
DHT22（GPIO 2）
    ↓ main.py 读取温湿度
SQLite（data/sensor.db：原始记录 + 小时汇总）
    ↓ web.py 查询并返回 JSON
浏览器（static/index.html + app.js + Chart.js）
    ↓
最新温湿度与历史曲线
```

采集与 Web 是两个独立进程，通过同一个 SQLite 文件交换数据，由 systemd 分别管理。

## 1. 启动和数据库初始化

- `main.py` 和 `web.py` 作为脚本启动时，都会调用 `db.init_db()`。
- 初始化会自动创建 `data/` 目录、`readings` 表、时间戳索引 `idx_readings_ts`、小时汇总表 `hourly_readings` 和状态表 `app_metadata`；重复调用不会重复建表。
- 每次访问数据库创建独立连接，启用 WAL 模式以支持采集写入与 Web 查询并发，并配置 10 秒锁等待时间；使用后关闭连接。

`readings` 表保存以下字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 自增主键 |
| `ts` | Unix 时间戳，单位为秒 |
| `temperature` | 温度，单位为 °C |
| `humidity` | 相对湿度，单位为 % |

## 2. 采集与保存（main.py）

1. 使用 `Adafruit_DHT.read_retry()` 读取 GPIO 2 上的 DHT22。
2. 如果温度或湿度为 `None`，打印失败日志并跳过本次保存。
3. 读取成功后记录当前时间，将温度、湿度四舍五入到两位小数，在同一事务中插入原始表、累加小时汇总并提交；任一步失败时一起回滚。
4. 单次采集或写入抛出异常时，主循环打印错误并继续运行。
5. 每轮处理结束后等待 60 秒，再进行下一轮，因此实际采样间隔还包含读取和写入耗时。

## 3. 页面与数据查询（web.py）

Web 服务监听 `0.0.0.0:8080`，使用 Bottle 和单线程 wsgiref。

| 路径 | 行为 |
| --- | --- |
| `/` | 返回 `static/index.html` |
| `/static/<path>` | 提供 JavaScript 等静态资源 |
| `/api/latest` | 按时间戳倒序查询最新一条记录；没有记录时返回 `{"ok": true, "data": null}` |
| `/api/readings?range=24h` | 查询指定时间范围，按时间戳升序返回历史记录 |

历史查询支持 `1h`、`24h`、`7d`、`30d`、`1y`、`3y`、`5y` 和 `all`（一年按 365 天计算），缺省或无效参数均使用 `24h`。除 `all` 外，以服务端当前时间减去范围时长作为查询起点。两个数据接口的记录均包含 `ts`、`temperature`、`humidity`，历史查询无数据时返回空数组。

1 小时和 24 小时查询原始表，由 SQLite 按整数时间桶分组求平均，最多返回 600 点。

7 天及更长范围使用 `hourly_readings`：每小时保存记录数、时间戳总和、温湿度总和和各自有效条数。按小时跨度分桶，将总和除以有效条数得到加权平均，避免直接平均小时均值造成偏差，结果最多 600 点。没有有效温度或湿度时对应值为 `null`。时间戳按实际记录的平均时间计算。查询起点落在小时中间时，仅该小时从原始表精确回查，其余从汇总表读取。所有分桶基于 Unix 秒，页面按浏览器本地时间显示。

旧数据库通过 `backfill_hourly.py` 在停服务后按 UTC 日分批回填。脚本可重复运行，清空并重建汇总，完成总条数、时间戳总和、温湿度有效条数及总和核对后，才设置就绪标记。没有就绪标记时自动回退到原始查询，避免使用未完成的汇总。新建空库直接就绪。部署和备份命令见 README。原始数据完整保留。

## 4. 浏览器展示与刷新（static/）

1. 页面加载本地 Chart.js 和 `app.js`，创建温度、湿度双纵轴折线图。
2. 首次进入时请求最新记录和最近 24 小时历史数据。
3. 用户切换时间范围按钮时，请求对应历史数据并更新图表。
4. 最新值每 30 秒刷新，上一次请求尚未完成时跳过本轮刷新；图表仅在首次加载或点击时间范围时查询，不自动刷新。时间戳按浏览器本地时间显示。
5. 历史查询期间禁用时间范围按钮并阻止重复请求，显示加载提示；成功后更新曲线和选中范围，失败时保留原曲线并提示重试，请求结束后恢复按钮。
6. 最新值无记录时显示“暂无数据”，请求失败时显示错误信息。

## 5. 部署与运行

- `deploy/thsensor.service` 启动采集脚本，`deploy/thsensor-web.service` 启动 Web 脚本，两者均配置自动重启，间隔 5 秒。
- 服务默认使用 `pi` 用户和 `/home/pi/file/RaspberryPI-THSensor` 目录，部署时需按实际环境调整。
- 服务标准输出和错误输出交给 journal，可使用 README 中的 `journalctl` 命令查看。
- Chart.js 文件未随当前代码提交，需按 README 下载到 `static/chart.umd.min.js`，供内网或断网环境使用。
- 当前代码持续追加采集记录，没有历史数据自动清理、告警或用户登录流程。
